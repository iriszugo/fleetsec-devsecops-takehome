# Insecure Direct Object Reference (IDOR) (CWE-639)

## 1. Executive Summary

| Field | Value |
|-------|-------|
| Vulnerability | Insecure Direct Object Reference (IDOR) |

| OWASP Top 10 | A01:2021 – Broken Access Control |
| Severity | High |
| Status | Mitigated |

---

## 2. Description

This laboratory demonstrates an Insecure Direct Object Reference (IDOR) vulnerability where user-controlled identifiers are used to access protected resources without verifying ownership or authorization.

The secure implementation enforces owner-based authorization and administrative access control before returning any protected resource.

---

## 3. Vulnerable Scenario

Example vulnerable implementation:

```javascript
const profile = users[req.params.id];

return profile;
```

The requested identifier is used directly without checking whether the authenticated user owns the requested resource.

---

## 4. Secure Implementation

The secure implementation validates ownership before returning the resource.

Security controls include:

- Owner validation.
- Administrator authorization.
- HTTP 403 responses for unauthorized access.
- Consistent authorization logic.

Example:

```javascript
const isOwner =
    profile.owner === authenticatedUser.id;

const isAdmin =
    authenticatedUser.role === "admin";

if (!isOwner && !isAdmin) {
    return res.status(403).json({
        error: "Access denied"
    });
}
```

## 8. Mitigation

Implemented controls:

- Owner-based authorization.
- Role-based administrator override.
- HTTP 403 responses.
- Automated regression tests.
- Static analysis using Semgrep.
